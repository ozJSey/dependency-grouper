# @ozjsey/dependency-grouper

Define a dependency set once, name it in a `package.json`, and every project that names it gets the
same versions.

> A CLI that rewrites `package.json` files on disk has no honest browser demo, so it has no tab in
> the [npm portfolio playground](https://ozjsey.github.io/npm-portfolio-playground/) — but that
> playground's own dependencies are managed by this tool.

## The problem

In a monorepo with multiple projects you have several React apps sharing the same React
dependencies, several Vue apps sharing Vue, and everything sharing the tooling — webpack, vite,
eslint. So you copy-paste dependencies across `package.json` files, keep the versions in sync by
hand, and update several places every time you upgrade one thing.

## The solution

Groups live in one `.dep-groups.yaml` at the root; a package opts into them by name.

```yaml
# .dep-groups.yaml
groups:
  react:
    dependencies:
      react: ^18.2.0
      react-dom: ^18.2.0
    devDependencies:
      '@types/react': ^18.2.0
  vue:
    dependencies:
      vue: ^3.5.17
```

```json
{
  "name": "my-vue-app",
  "depGroups": ["vue"],
  "dependencies": { "axios": "^1.6.0" }
}
```

`dependency-grouper generate` merges each package's named groups into its `dependencies` /
`devDependencies`, sorted, and lifts any version a member has drifted on back up into the group.

**Never bootstrap with `"depGroups": []`.** `generate` pours *every* non-root package's
dependencies into one flat `standalone` group and hands that whole group back to *every* non-root
package — a React app and a Vue app in the same tree each come out depending on both. Merge is
additive, so splitting the group up afterwards does not take anything back out: the only way back
is to edit each member's `dependencies` by hand. Draft with `sync`, which writes no manifest at
all, and name real groups before the first `generate`.

pnpm, npm and yarn workspaces all work — and so does **no workspace at all**: a `.dep-groups.yaml`
is itself a valid root, checked before any workspace marker, so a flat set of sibling folders that
each carry their own `node_modules` can be grouped too. That is the shape this package lives in:
dropping one config file into the playground directory was the entire setup, and nothing about the
repo's structure had to change.

## Install

```bash
pnpm add -D @ozjsey/dependency-grouper   # or npm / yarn
```

Requires Node 16 or newer. The CLI is `dependency-grouper` (or `dep-grouper`).

`generate` injects a **`preinstall` hook into every package it manages**, the workspace root
included, and there is no flag to turn that off. The command it writes is guarded —
`dependency-grouper generate || exit 0` — because `preinstall` runs *before* dependencies are
installed, so on a fresh clone the CLI is not on PATH yet and the bare command aborts the install
with `code 127`. **Manifests generated by an older release carry the unguarded string, and
`generate` will not repair them**: any `preinstall` already mentioning `dependency-grouper` is left
alone by design. If a fresh clone of your repo fails its first install with 127, that is this — add
the `|| exit 0` yourself.

Because npm runs a dependency's `preinstall` on the *consumer's* machine, a **published** package
should not be managed by this tool at all unless you are willing to ship that hook to everyone who
installs it.

## Usage

### A new tree

```bash
# 1. Write .dep-groups.yaml at the root, 2. name the groups in each package.json, then:
npx dependency-grouper generate
pnpm install
```

### Adopting a tree that already has dependencies

`sync` drafts the config from what your packages already declare and **only ever writes
`.dep-groups.yaml`** — no manifest is modified, which is what makes it the safe first step:

```bash
npx dependency-grouper sync          # drafts .dep-groups.yaml from the existing manifests
code .dep-groups.yaml                # split the drafted `standalone` bucket into real groups,
                                     # then delete `standalone`
# packages/react-app/package.json → "depGroups": ["react"]
# packages/vue-app/package.json   → "depGroups": ["vue"]
npx dependency-grouper generate      # now each package gets its own groups and nothing else
```

Afterwards `standalone` is a useful signal rather than a bucket: an entry appearing there means a
dependency was added without being classified.

### Moving a shared version

**Not by editing `.dep-groups.yaml`.** `generate` syncs `package.json` → config *before* it merges
config → `package.json`, so an edit to a version already present in a member is overwritten before
it is applied. `.dep-groups.yaml` owns membership; `package.json` owns versions.

```bash
# Change the version in the member package.json files. Changing it in the LAST package in
# directory order is enough — sync lifts that value into the group, and merge pushes it down:
npx dependency-grouper generate
pnpm install
```

Adding a *new* dependency to a group in the config does work — no member declares it yet, so it
flows down to all of them.
